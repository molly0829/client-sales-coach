# 客户档案模板与多客户管理

> 一个客户 = 一张"活案卷"。跨会话累积，避免断片。
> **敏感信息脱敏**：客户名用代号，联系人用"王主任""张经理"这类称呼，不写手机号、不写报价原文。

---

## 一、目录结构

```
profiles/
├── _index.md            # 全局看板：所有客户一行一个
├── 恒远制造.md           # 单客户档案（文件名=代号）
├── 华东城投.md
└── ...
```

`profiles/` 不要提交到公开仓库（加入 `.gitignore`）。

---

## 四、建档与更新规则

### 首次建档
1. 根据用户提供的信息，填完"基本信息 + 决策链 + 当前状态 + 痛点"。
2. 把档案**完整展示一次**给用户确认/补正。
3. 问一句："要不要我存成文件（`profiles/<代号>.md`）长期跟踪？"

### 后续更新
- 每次分析后，把新信息并入对应字段，更新"最近更新"日期。
- 阶段/概率变化时，同步更新 `_index.md` 那一行。
- **不必每条回复都重贴整块档案**，只靠开头的阶段标签体现即可。

### 什么时候展示完整档案
- 用户说"看看这个客户的档案""复盘一下"。
- 阶段发生明显变化。
- 每周盘点的场景。

## 五、脱敏要求

- 客户名：用"行业+特征"代号（"恒远制造""华东城投"）。
- 联系人：用"姓+职位"（"王主任"），不写全名、手机、微信。
- 金额：可写区间或"约 XX 万"，不写精确报价单。
- 聊天记录：粘贴前提醒用户删除真实姓名、电话、身份证号、合同编号。

> 如果用户坚持用真名，也可以，但提醒一次风险（尤其是要放到 Git 仓库或云端时）。

---

## 六、多客户并行的心法

1. **每个客户独立成档**，绝不串用信息（A 客户的预算不能套到 B 客户）。
2. **每周盘点一次**：四栏分类（本周必推 / 正常跟进 / 观察 / 已止损）。
3. **控制"活跃客户"数量**：超过 15 个活跃客户，单个客户的推进质量必然下降。
4. **给每个客户设"下一次动作日期"**，过期未做的，要么补上，要么降级。
